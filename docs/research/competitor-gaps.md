# Research: Competitor and gap analysis (VueScan, ExactScan, NAPS2, ScanSnap Home)

_Generated by research agents, July 28 2026. Confidence: high_

## Findings

## 1. VueScan (Hamrick) — 2026

**fi-8170 support**: Officially supported on macOS/Linux with VueScan's OWN built-in driver ("You can use this scanner on Mac OS X and Linux without installing any other software"), i.e. it bypasses ICA entirely. Notable: "VueScan uses in-scanner JPEG compression with this scanner to scan faster. You can turn this off by setting 'Input | Fine mode'" — in-scanner JPEG at 600dpi is a quality/speed tradeoff our spec should surface explicitly. Film scanning: No; optical 600dpi; ADF: yes. (https://www.hamrick.com/vuescan/fujitsu_fi_8170.html)

**Naming tokens** (Output tab, https://www.hamrick.com/vuescan/html/vuesc33.htm):
- `+` = serial counter: "Insert a plus sign (+) anywhere in the filename after some digits… to create a new unique filename in the folder". Counter value derives from digits preceding the `+` (e.g. `crop0001+.tif` → crop0001, crop0002…); `+2` sets increment step. Critically it is "next unique name in folder" semantics, not a persistent per-job counter — renaming/moving files or pointing at a new folder silently resets the sequence.
- `@` = date template: expands to `Scan-YYYY-MM-DD-0001+`. Defaults: TIFF `@.tif`, JPEG `@.jpg`, PDF `@.pdf`, OCR `@.txt`, Raw `scan0001+.tif`.
- `=` inserts current Input|Frame number; `*` reuses raw input file name.
- NO side/front-back token exists — nothing that can produce `scan_000114_F.jpg`/`_B.jpg` pairs sharing one counter.

**Duplex handling** (https://www.hamrick.com/support/frequently-asked-questions/how-do-i-scan-both-sides-of-a-document.html): duplex = "Input | Mode: Duplex Feeder". Front/back are emitted as sequential frames (counter 0001=front, 0002=back) or combined via "Front/Back" multi-page option into one file; for non-duplex hardware the workaround is scan-fronts, scan-backs, right-click "Interleave" in a multi-page PDF ("you need exactly the same number of front sides and back sides"). No paired naming, no per-side rotation profiles as first-class UI.

**Crop/border**: Crop tab has `Border` as a % of the cropped area, may be negative to shrink; the added border "is ignored when computing the color balance" (https://www.hamrick.com/vuescan/html/vuesc30.htm). Auto-crop for documents/receipts/cards added in 9.8.06/9.8.13 (https://www.hamrick.com/blog/vuescan-9-8-13-autocrop-receipts-and-documents.html).

**UX failure modes (cited)**:
- alternativeto.net comments: "Do NOT waste your money. Unintuitive, clunky and unreliable… Doesn't support a whole suite of scanners and there's no way to tell until your money is gone" (merckle, 2019); support form requires log attachments, dev dismissive (io41, 2019) (https://alternativeto.net/software/vuescan/about).
- G2: "interface feels like old Windows" (https://www.g2.com/products/vuescan/reviews).
- Preview≠scan mismatch threads: https://rangefinderforum.com/threads/vuescan-mismatch-between-preview-and-scan.158720/ and https://rangefinderforum.com/threads/vuescan-previews-disappear.153155/
- analog.cafe review (Mar 2025): controls "overwhelming and frustrating", arbitrary guess-and-check measurements, "may be a little frustrating navigating batch scanning jobs via VueScan 9" (https://www.analog.cafe/r/vuescan-professional-review-jq26).
- File-naming path-vs-name confusion is a recurring forum topic (folder must go in "Default folder", name construct in filename box): https://www.pcreview.co.uk/threads/vuescan-file-naming.1939396/
- DPReview opinion thread (mixed, UI learning curve): https://www.dpreview.com/forums/threads/your-opinion-about-vuescan-software.3680569/ (DPReview 403s fetchers; snippet-verified only).

**Pricing/licensing (hamrick.com/purchase-vuescan.html, July 2026, promo ending Jul 29)**: Standard $89.95 one-time (list $99.95), $29.96/yr (list $39.95), $7.46/mo; Professional $179.95 one-time (list $199.95), $59.96/yr (list $79.95), $14.96/mo. One-time purchase = only 1 year of free updates (the old "Pro = lifetime updates" deal is gone; Wikipedia still describes the older model). Personal license covers 4 computers; free version watermarks scans. Recurring complaints: watermark, "costly renewal".

## 2. ExactScan Pro (ExactCODE) — the closest real competitor

**Status**: Actively maintained. v26.x line; 26.6 released Jun 11 2026 (builds to 26.6.20); v26 adds macOS 26 "Tahoe" support, new scanner models, improved auto-crop/deskew; Pro 26 adds better OCR and large-PDF handling (https://exactscan.com/, https://mac.softpedia.com/get/System-Utilities/ExactScan.shtml, https://filecr.com/macos/exactscan-pro/). Sold direct (anti-App-Store stance). Also now ships Windows/Linux "universal" version (https://exactscan.com/universal/).

**fi-8170: YES, built-in driver** (no ICA needed). Compatible list explicitly includes fi-8040/8150/8170/8190/8250/8270/8290, fi-7030/7140/7160/7180, fi-6xxx, fi-800R (http://exactscan.com/compatiblescanner.shtml). "500+ built-in drivers" for Avision/Canon/Fujitsu/Kodak/etc.; can also drive third-party TWAIN and ImageCapture(ICA) drivers.

**Job/profile concept**: customizable profiles ("Define your own personal profiles"), one-click profiles that scan straight to a folder or trigger AppleScript; button manager maps scanner hardware buttons to profiles. Naming tokens: "sequence number, page number, date or barcode". 1D barcode naming/splitting (Pro): "name or split batches by common barcodes"; 2D Datamatrix/PDF-417 (Enterprise). Blank-page detection, deskew, auto paper-size crop, OCR in 25 languages (Pro), imprinting, append-to-PDF. No review/hold/release queue documented — output goes straight to files.

**Pricing** (https://exactco.de/store.shtml): ExactScan 70€, Pro 100€, Enterprise 250€ one-time; upgrades 40/60/200€ from any previous version.

## 3. NAPS2 on macOS

**License — common misconception corrected**: the NAPS2 app is GPL-2.0-or-later; NAPS2.Sdk and NAPS2.Escl/Images/Internals are LGPL-2.1-or-later; only NAPS2.Sdk.Samples is MIT (https://github.com/cyanfish/naps2). Forking the app into a proprietary product is not viable (GPL); embedding the SDK means shipping .NET runtime + LGPL compliance in a C# stack — unattractive inside a native Swift app. Verdict: build native (ImageCaptureCore is a first-party Apple framework; NAPS2's Apple driver is itself just an ICC wrapper). Reading NAPS2's Apple driver source as a behavioral reference for ICC quirks is the only value worth extracting.

**Current state**: v8.3.2 latest in changelog (Mac fix: "Fixed error with save/import"); requires macOS 12+; free. Drivers on Mac: Apple (ImageCaptureCore, default — reaches TWAIN+ESCL devices via ICA), ESCL (own implementation, network scanners), SANE (older USB on Apple Silicon) (https://www.naps2.com/mac-scanning, https://deepwiki.com/cyanfish/naps2/4.1-scanner-drivers).

**Features**: profiles (per-device settings incl. duplex, "Flip duplexed pages" advanced option); batch scan dialog with 3 modes ("Single scan", "Multiple scans (prompt between scans)", "Multiple scans (fixed delay)"); output "Save to a single file"/"Save to multiple files" with "One file per scan"/"One file per page"/"Separate files by Patch-T" (patch codes need ≥300dpi); naming placeholders $(n)/$(nn)/$(nnn)/$(nnnn) + $(YYYY)$(MM)$(DD); Tesseract OCR; full CLI (https://www.naps2.com/doc/batch-scan).

**Where it falls short of PaperStream-class**: (a) placeholders broken with autosave — files literally named `$(nnn)`, open bug in 8.1.4 (https://github.com/cyanfish/naps2/issues/622); (b) counters are "next unique in folder", no persistent per-profile counter, users ask for a settable starting count (https://sourceforge.net/p/naps2/discussion/general/thread/8268d22849/); (c) no front/back side token, no pair naming; (d) no review-then-release gate — thumbnails can be edited before manual save, but autosave/batch writes immediately and there's no hold queue/rescan-replace; (e) Mac driver flakiness history: Apple-driver duplex returned only fronts on macOS 13 (fixed 7.0b4, https://github.com/cyanfish/naps2/discussions/35), duplicate pages/forgotten reverse sides, ADF→flatbed profile switch blocks scanner (https://github.com/cyanfish/naps2/issues/681), "Big problems with both Apple and ESCL drivers on iMac" (https://sourceforge.net/p/naps2/discussion/general/thread/0ed2469b78/); (f) Eto.Forms UI, not native-feeling.

## 4. Other Mac contenders 2024–2026

- **ScanTango**: dead. v2.6.8, May 22 2015, $99, no OCR ("What a joke for this price and no OCR") (https://scantango.macupdate.com/).
- **Prizmo 5** (Creaceed): photo-OCR positioning, macOS 14+, v5.0.2; handles "multiple page groups in a single document" from feeder batches but is not an ADF batch frontend (https://setapp.com/apps/prizmo, https://creaceed.com/prizmo — note: creaceed.com has a broken TLS chain for fetchers). **Prizmo Remix** is their newer "scanner automation for Mac" app (App Store, Pro Pack IAP/subscription) — watch it, but it targets office docs, not counter-named batch output (https://creaceed.com/prizmoremix).
- **Card Dealer Pro** (carddealerpro.com): proves the exact card-scanning niche — sells fi-8170 bundles and officially requires **Windows + PaperStream Capture** for trading cards; publishes fi-8170 card-scanning settings guides (https://support.carddealerpro.com/hc/en-us/articles/9624488762011-Ricoh-8170-Settings-Configuring-PaperStream-Capture-to-Scan-Trading-Cards-and-Sports-Cards, https://www.carddealerpro.com/best-card-scanners/ricoh-fujitsu-8170). Mac users in this niche currently have NO sanctioned path — that's our wedge.
- **ScanSnap Home** (PFU/Ricoh's own consumer Mac app; ScanSnap hardware only, NOT fi series) — UX reference (https://www.pfu.ricoh.com/global/scanners/scansnap/sshome/): profiles bundle destination+cloud+format+color+quality and render as one-tap touchscreen tiles; auto-classifies scans into "documents, receipts, business cards, and photos"; content-based name suggestions ("uses text, such as shop and company names… to recommend file names") that learn from user edits; auto date extraction to Exif; Quick Menu destinations (Teams/SharePoint/OneNote/Notion/iCloud); folders/tags/keyword search. What it gets WRONG (equally instructive): Michael Tsai — "the new ScanSnap Home software is ugly and awkward", cloud-pushy enough that users firewall it with Little Snitch, redeeming feature is that you can ignore the app and press the hardware button (https://mjtsai.com/blog/2024/07/11/ricoh-scansnap-ix1600/).
- Apple **Image Capture**: the default fallback; minimal (no naming rules/counters/profiles/review), widely dismissed ("Image Capture is considered poor quality scanning software" per AnandTech thread https://forums.anandtech.com/threads/best-scanning-software-for-os-x.2250085/).

## 5. Recurring user pains = differentiator checklist

1. Dated/overwhelming, non-native UI (VueScan "old Windows"; ScanSnap Home "ugly and awkward"; NAPS2 Eto.Forms; ExactScan utilitarian). → Modern native SwiftUI is a real differentiator, not cosmetics.
2. Naming is weak, cryptic, or buggy: VueScan's `+/@/=` glyph tokens + folder/name field confusion; NAPS2's open placeholder-autosave bug #622; nobody has a duplex side token or pair naming (`_F`/`_B` sharing one counter). → First-class naming-rule builder with live preview, persistent per-job counters, explicit start/step/reset, side token.
3. Counter semantics are "next unique filename in folder" everywhere — fragile, resets silently, no settable start (NAPS2 sourceforge thread). → Durable counter stored in job state, shown in UI, editable, monotonic across sessions.
4. No review-then-release anywhere on Mac: every competitor writes files immediately; PaperStream's verify→rescan/replace→release batch gate has zero Mac equivalent. → This is the single biggest structural gap.
5. Duplex/ADF fragility at the driver layer: NAPS2 Apple-driver duplex bugs, duplicate/missing reverse sides, ADF↔flatbed switch hangs; users told to trial-and-error between Apple/ESCL/SANE backends. → Own the fi ICA driver integration deeply; per-side rotation; deterministic front/back pairing with detection of odd-page (multifeed/miss) conditions.
6. "Will my scanner even work?" uncertainty pre-purchase (alternativeto complaint) → publish explicit supported-model matrix; free trial without watermark sabotage.
7. Licensing resentment: VueScan watermark + 1-year update clock + renewal nags; ScanTango $99 with no OCR. ExactScan's clean one-time 70–100€ is the goodwill benchmark.
8. Cloud-pushiness / privacy: ScanSnap Home users deploy Little Snitch against it. → Local-first, cloud optional.
9. Preview/scan mismatch and trust (Rangefinderforum threads) → what-you-review-is-what-you-get pipeline.
10. Speed vs quality opacity: VueScan silently uses in-scanner JPEG compression on fi-8170 unless "Fine mode" — at 600dpi duplex for collectibles, compression/quality must be explicit in the job profile.

## Recommendation

Position against ExactScan Pro (the only live Mac competitor with a built-in fi-8170 driver, 100€ one-time) rather than VueScan, and differentiate on the two structural gaps NOTHING on Mac has: (1) a PaperStream-style review-then-release batch gate (scans land in a hold queue with verify/rescan-replace/delete, files+counters commit only on release — make counter commitment transactional so an aborted batch never burns numbers), and (2) first-class pair naming: a naming-rule builder with live preview, persistent per-job counters (visible, editable start/step, monotonic across sessions — never "next unique filename in folder"), and an explicit side token so scan_000114_F.jpg/_B.jpg is a template, not a hack. Steal: ExactScan's token set (sequence/page/date/barcode) and profile→folder/AppleScript triggers; ScanSnap Home's one-tap profile tiles and (later) content-aware name suggestions — but local-first, no cloud nagging; VueScan's crop Border-% (retain sleeve edge margin, exclude it from color balance) and its in-scanner-JPEG lesson (surface compression on/off per profile at 600dpi). Do NOT fork/embed NAPS2: the app is GPL-2.0-or-later and the SDK is LGPL-2.1 .NET (a common MIT assumption is wrong — only its samples are MIT); build native Swift on ImageCaptureCore, using NAPS2's Apple-driver bug history (duplex fronts-only, duplicate pages, ADF↔flatbed hangs) as a QA checklist for the ICA layer. Spec explicit handling for duplex pairing failure modes (multifeed/odd page count breaks F/B pairing — detect and quarantine in review). Pricing: one-time license around ExactScan's 70–100€ band with honest trial; avoid VueScan's watermark+renewal model, which is the single most-cited goodwill killer.
